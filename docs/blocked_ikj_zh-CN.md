# CPU 缓存分块实验

[English](blocked_ikj_en.md)

## 内核与验证

`matmul_cpu_blocked_ikj` 按 `ii → jj` 遍历输出块，再按递增的 `kk` 遍历归约块。块内按 `i → k → j` 遍历，使每个输出元素沿用基线的递增 K 累加顺序，最内层连续访问 B 和 C。内核只清零 C 一次，BM、BN、BK 可独立设置为正数，尾块按剩余尺寸截断。构建采用严格 FP32 运算。两个内核使用相同的编译选项和行主序输入缓冲区。

数值测试逐位比较分块结果与现有 FP32 `ikj` 基线，并独立记录相对于 double 累加参考实现的逐位匹配数、绝对误差、相对误差和 ULP 距离。普通有限值使用 `1e-4 + 1e-3 × abs(reference)` 容差。相对误差沿用现有数值测试的规则，分母下限为最小正正规数。覆盖边长 1、31、32、33、255、256、257 的方阵，以及 31×32×33、127×257×63、33×17×65 的矩形组合。每组检查五种立方块和 7×16×3、3×5×2 两种独立块形状，另检查空输出、K=0 和块尺寸为零的行为。

强抵消样例使用 `[1e10, -1e10, 1, 1, 1e10, -1e10, 1, 1]` 与全 1 列。两个严格 FP32 内核均返回 2，double 参考实现返回 4。测试显式核对这些结果，并记录预期的参考容差超限。其余样例必须通过现有容差且与 FP32 基线逐位一致。

## 复现

环境为 AMD Ryzen 7 7730U、WSL2 Ubuntu、GCC 15.2.0，采用 C++17 Release 与 `-O3 -DNDEBUG`、`-Wall -Wextra -Wpedantic`。Linux 可见 8 核、16 个逻辑处理器。计时与硬件计数进程均固定于逻辑处理器 4。每核 L1D 为 32 KiB、8 路组相联、64 组、64 字节缓存行。每核 L2 为 512 KiB、8 路，共享 L3 为 16 MiB、16 路。

```bash
cmake -S . -B build-blocked -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build-blocked -j4
ctest --test-dir build-blocked --output-on-failure
python3 benchmarks/run_blocked_experiment.py build-blocked /tmp/blocked-reproduction --cpu 4
./build-blocked/cpu_benchmark blocked-sweep 127 257 63 7 16 3
objdump -d -C build-blocked/CMakeFiles/matmul_cpu.dir/src/cpu/blocked_ikj.cpp.o
```

扫描使用确定性 FP32 输入。每个尺寸启动两个独立进程，每个进程对各配置预热五次，在计时外与参考实现核对。每个进程按确定性打乱的顺序采集 21 轮。边长 128 每次计时合并七次调用，其余尺寸每次计时一次调用。计时包含清零 C，各配置使用相同的预分配缓冲区。吞吐量为 `2 × M × N × K / 时间`，加速比为基线中位数除以分块中位数。

## 数值结果

77 组尺寸与块形状均与严格 FP32 基线逐位一致，共比较 1,637,146 个元素，含各块形状的重复核对。70 组普通输入中，1,637,139 个元素比较有 192,612 个与 double 参考逐位一致。相对参考实现的最大绝对误差为 1.62125e-5，最大相对误差为 0.034902，最大 ULP 距离为 351,798。普通输入全部通过联合容差，数值分类与有符号零均无不匹配。强抵消样例的七种块形状相对 double 参考的绝对误差均为 2，相对误差均为 0.5，ULP 距离均为 8,388,608。

## 硬件计数

使用 `perf stat` 采集记录中的六个用户态事件。每行取三个独立进程的中位数，先将各进程计数除以固定调用次数。IPC 为各进程指令数除以周期数的中位数。除 IPC 外，所有计数的单位均为百万次事件每调用。计数仍包含启动、分配、输入生成和一次校验和计算。进程重复执行内核，不计算参考实现。WSL 提供了所请求的通用事件，事件运行比例均为 100%。没有使用或替换为处理器型号专用事件。通用缓存事件沿用其 perf 名称，不将其归到特定缓存层级。

## 已建立结论与待验证问题

**实测事实。** 本实验以中位加速比超过 1.05×、且至少 90% 的配对轮次更快定义稳定收益。没有尺寸达到标准。128 块在各尺寸均是中位数最快的分块候选。在边长 128 时它覆盖整个矩阵，中位加速比为 1.006×，但仅 42 轮中的 16 轮更快。511 的最快分块为 0.973×，1024 为 0.931×。额外测试的 256 块在两个测点均比 128 块使用更多周期。已测网格内最快的立方块没有随尺寸变化。独立 BM、BN、BK 仅做了正确性验证。

**计数器与汇编依据。** 在 128 和 511 上，8 块的 L1D 读取未命中少于基线，但指令数约为 2.5 倍，周期约为 3 倍。GCC 对相邻输出列生成打包的 `mulps`、`addps` 及标量路径。分块增加循环和边界处理，并缩短连续内层循环。计数支持额外指令开销的解释。在 1024 上，128 块的指令和所报告的未命中也高于基线。现有观测无法逐项分离耗时差距，也不能判断每个块的实际缓存驻留情况。

**待验证。** 更大的矩阵、非立方块以及面向本机指令集的严格构建都可能改变结果。仅凭缓存容量不能确定驻留。行步长、组相联、缓存行利用率、竞争数据和硬件预取都可能影响表现。现有结果未分离这些效应，也未建立通用的收益交叉点。
