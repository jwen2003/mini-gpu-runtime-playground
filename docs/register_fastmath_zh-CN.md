# 寄存器分块与快速数学编译实验

[English](register_fastmath_en.md)

在 1024 方阵上，严格寄存器分块采用 4×16 微块和 128³ 外层块，耗时 88.315 毫秒。完整内核相对原始严格 `ikj` 加速 **1.466×**（129.510 / 88.315），相对严格缓存分块加速 **1.541×**（136.114 / 88.315）。

## 实验方法

比较原始 `ikj`、缓存分块 `ikj`、寄存器分块 `ikj` 三种内核。每种内核的快速版与严格版从同一源码构建。仅独立静态库 `matmul_register_fast` 启用 `-ffast-math`，参考实现与实验框架采用默认严格构建，可执行文件的链接命令不使用快速数学选项。本轮沿用第一阶段的 x86-64、GCC 15.2.0 与 Release 配置（`-O3 -DNDEBUG`），使用 128 位 SSE，未启用面向本机的指令集选项。SSE 是 x86-64 的基础能力。CMake 选项默认关闭，并检查目标架构和编译器。

寄存器分块在一个 K 归约块内为每个输出通道保留一个累加器。驱动层按 `ii → jj → kk` 遍历。完整微块在 K 循环前读取 C，结束后写回。M/N 尾块走按递增 K 累加的边界路径，K 尾块按剩余深度截断。主外层块为 128³，敏感性对照为 64³。每种外层块下的候选微块为 2×8、4×8、4×16，8×16 用作高寄存器压力对照。

在 Ryzen 7 7730U、WSL2 Ubuntu 环境下，每个方阵尺寸启动两个独立进程。每个配置预热三次，之后每个进程交错采集九轮。输入由固定种子生成，两个进程使用不同的固定顺序种子。尺寸 128 每个计时样本合并七次调用，其他尺寸各一次。分配、输入生成和正确性核对位于计时区间外。为控制 22 种配置重复测量的开销，省略可选的 2048 尺寸。本轮分块实验仅覆盖当前处理器与构建，未测其他处理器以及 AVX2、面向本机指令集或启用 FMA 的构建。

```bash
cmake -S . -B build-register -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -DMINI_GPU_BUILD_REGISTER_EXPERIMENT=ON
cmake --build build-register -j4
ctest --test-dir build-register --output-on-failure
python3 benchmarks/run_register_experiment.py build-register /tmp/register-reproduction --cpu 4
```

## 汇编与寄存器溢出

原始和缓存分块的向量循环在每个 k 读取并写回 C。微内核用 `movss` 与 `shufps` 广播 A，以 `mulps` 和 `addps` 更新不同输出列。GCC 展开固定的行与向量通道，热循环每次推进一个 K 步。四种完整微块的严格与快速版反汇编一致。这些循环中未生成 FMA 或水平归约。

栈空间取自 `sub ..., %rsp`，不含被调用者保存寄存器的压栈和红区用量。原始内核严格版和快速版分别预留 104 和 88 字节。缓存分块两版均预留 264 字节。下表统计各微内核 K 回跳区间内的向量栈操作数，包含算术指令的栈内存操作数。

| 微块 | K 循环地址范围 | 预留栈字节数 | 每个 K 步的向量栈访问数 | C 的读写 |
|:---|:---|---:|---:|:---|
| 2×8 | 0x40–0x7e | 0 | 0 | 每归约块读写 |
| 4×8 | 0x110–0x18a | 0 | 0 | 每归约块读写 |
| 4×16 | 0x2c0–0x3c7 | 32 | 12 | 每归约块读写，有溢出 |
| 8×16 | 0x720–0x999 | 432 | 44 | 每归约块读写，有溢出 |

例如 4×16 在 0x2e2 用 `addps -0x78(%rsp),%xmm15` 更新溢出向量，随后在 0x2e8 用 `movaps %xmm15,-0x78(%rsp)` 写回同一槽位。8×16 在 0x74f/0x755 对 `-0x68(%rsp)` 执行同类操作。溢出流量可能命中 L1D，循环内的栈访问本身就是溢出证据。

## 结论与调度建议

- **实测事实。** 单独缓存分块在已测范围没有稳定收益。外层块为 128³ 时，4×16 在每个尺寸上都是两种策略中三个预定微块里最快的。8×16 压力对照独立于该候选排名。严格 4×16 在每个尺寸的两个独立批次中均快于两个严格基准。在 1024 上相对原始严格 ikj 为 1.466×，相对严格缓存分块为 1.541×。将 128³ 的耗时除以 64³ 的耗时，严格 4×16 得到 0.951×–1.011×，快速版为 0.953×–1.009×。高压力对照 8×16 虽有溢出，部分测点仍更快。更多复用或并行性可能抵消溢出成本，各自的贡献尚未测定。
- **汇编与硬件计数。** 在 1024 上，相比严格缓存分块，严格 4×16 每次调用将指令数从 2,364.515 百万降至 1,095.439 百万，存储派发从 270.504 百万降至 107.625 百万。两个较小微块在完整 K 循环中消除了 C 的重复读写，且无向量溢出。较大的微块移除了对 C 缓冲区的重复访问，但反复读写栈槽。8×16 比 4×16 的存储派发更多，L1D 加载未命中却更少，与部分溢出访问命中缓存相容。
- **快速数学与交互。** 主对照中的 4×16 快速寄存器分块加速比为 0.975×–1.033×，四种微内核的严格与快速版主体一致。128 和 256 的交互系数接近 1。1024 的表观正交互最大，为 1.157×。两个批次分别为 1.093× 和 1.108×，主要来自快速缓存分块对照变慢。1024 的硬件计数也显示快速缓存分块周期数较高（499.086 百万对 433.675 百万）。这是所测版本间的差异，尚不足以证明重结合改善微内核或交互可推广。
- **待验证。** 两种编译策略在完整微块循环之外的机器码有差异。数据尚未分离循环外寄存器分配、访存调度、缓存行为、频率波动或 WSL 的影响。矩形和更大尺寸的性能仍需实测。
- **调度。** 在严格策略下，将 128³ 外层块与严格 4×16 作为已测方阵负载的首选实验候选，未验证的形状和平台保留严格原始内核作为回退。AllowReassociation 策略允许调用快速内核，也可继续选择严格寄存器分块。启用快速路径应要求显式策略和目标负载上可重复的收益。样例逐位一致并不构成快速数学的严格语义保证。

下一步测量矩形与尾块占比高的尺寸的收益交叉点。固定 SSE 4×16 输出形状，对比降低同时存活向量数的实现，通过热循环栈操作与存储派发验证变化。面向本机指令集或启用 FMA 的测试独立进行，并明确记录乘加融合策略和逐位结果。

后续实验沿用严格 SSE 和相同外层块，对照 4×16 测量了三个等累加器微块。后续结果使用独立采集的配对计时数据。[严格 SSE 微块形状探索](../experiments/blocked_ikj/ryzen7730u/microtile_search/report_zh-CN.md)
